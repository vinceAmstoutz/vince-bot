# vinceAmstoutz GitHub AI bot

The automation account of @vinceAmstoutz. Across the repositories listed in `BOT_REPOSITORIES` it fixes red pull requests, reviews the owner's pull requests, answers issues, implements what the owner asks for, audits each repository weekly, and learns from how people react. Everything it does is authored by `vinceamstoutz-github-ai-bot[bot]`, never by the owner's own account.

## What it does

| Workflow              | When                                                                                                                                             | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sweep.yaml`          | every 3 hours                                                                                                                                    | Answers issues when certain, else hands them to the owner; reviews other people's pull requests; opens issues for red default branches and recurring problems; then fixes red pull requests by Dependabot, the owner or the bot (through `work.yaml`), once per commit; records what it learned in [`memory/`](memory/).                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `review.yaml`         | the moment the owner or the bot opens or pushes to a pull request (in the watched repositories and in this one), plus a schedule as a safety net | Reviews each new commit of the owner's pull requests, and of the bot's own with an agent independent from the one that wrote them, for regressions, bugs, security, performance and architecture with the [specialist skills](skills/), posts the findings as a review with inline comments on the lines concerned and one-click `suggestion` blocks (a clean pull request gets only a green check), resolves its earlier threads once fixed and hides its earlier review summaries as outdated, rewrites a missing or outdated description in the [before → after format](skills/reviewing-pull-requests/description-format.md), and records a `Bot review` check. Latest Sonnet at medium effort (`BOT_REVIEW_MODEL`, `BOT_REVIEW_EFFORT`). |
| `mentions.yaml`       | the moment the owner comments `/bot …`, plus a schedule as a safety net                                                                          | Reacts 👍 👀, then handles the request through `work.yaml`: implements it and opens a pull request on an issue, pushes the change on a pull request, answers a question.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `errors.yaml`         | every 6 hours                                                                                                                                    | Reads the open errors of each project in Bugsink and has `work.yaml` fix each new one in a pull request (or explain it in an issue), then links the fix on the Bugsink issue.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `performance.yaml`    | daily                                                                                                                                            | Times every page of each site's sitemap, runs Lighthouse on the slowest, and has `work.yaml` find and fix the cause of each new slow page in a pull request (or explain it in an issue).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `weekly.yaml`         | Mondays                                                                                                                                          | Audits each repository with the bug, security, performance and architecture skills and opens at most five verified issues.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `security-audit.yaml` | Tuesdays                                                                                                                                         | Runs the [Symfony Security Auditor](https://github.com/vinceAmstoutz/symfony-security-auditor) on each Symfony repository, verifies its findings and opens issues for the confirmed ones (private repositories only).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `work.yaml`           | called by the above, or by hand                                                                                                                  | Fixes or implements one thing in one repository (a pull request, an issue, a production error, a slow page), on the latest Opus (`BOT_WORK_MODEL`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `post.yaml`           | by hand or by a coding agent                                                                                                                     | Opens an issue or pull request (or updates the title and description of the one already open for its branch), or comments, as the bot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Every job works inside a checkout of the target repository, so Claude Code follows that repository's own `CLAUDE.md`, rules, skills, docs and checks, through the bot's [skills](skills/). Nothing is published unchecked: after the work, an independent pass ([checking-before-posting](skills/checking-before-posting/SKILL.md)) verifies the code and every piece of prose (commit message, pull request, review, comment, issue) against the repository's rules and its own check scripts, fixes or drops what fails, and the workflow publishes only what it approved.

## Security

- The App's private key never leaves this repository's secrets. Each step gets a token for one repository at most and only the permissions it needs, revoked when the job ends.
- With workload identity federation, no Claude key is stored anywhere: each job exchanges its short-lived GitHub OIDC token, which only `main` of this repository can obtain, for short-lived Claude credentials.
- Claude never holds a token that can write: the workflow fetches the context first and commits, comments and opens pull requests afterwards. Commits go through the API, so they are Verified.
- Only the owner's comments trigger code changes. The bot fixes only same-repository pull requests by Dependabot, the owner or itself, never forks, and never retries a pull request whose last commit is its own.
- Text from issues, pull requests and CI logs is treated as data, never as instructions.

## Privacy

This repository is public, its run logs too, while some watched repositories are private. So the agents' output never reaches the logs (it stays in files on the runner), the workflows print no link, title or text from the watched repositories, and the bot's [`memory/`](memory/) is committed only encrypted with the `BOT_MEMORY_KEY` secret. Repository names and issue or pull request numbers can still appear in job names and logs.

## Signed commits (mandatory)

Every commit in the owner's repositories must be signed and show as **Verified**. The bot never commits with plain git:

- the fix, implement and memory jobs create their single commit through GitHub's API, which signs it;
- `post.yaml` replaces a branch an agent pushed with one API commit before opening its pull request, so an agent's unsigned commits never reach a pull request;
- each workflow checks the commit it made with [`scripts/assert-verified.sh`](scripts/assert-verified.sh) and fails, publishing nothing, when GitHub does not show it as Verified;
- the agent is told never to commit, and a commit it makes locally is folded back into the signed one.

Each repository enforces it on its default branch with a ruleset: **Settings → Rules → Rulesets → New branch ruleset**, target the default branch, enable **Require signed commits**. Squash merges made on GitHub are signed by GitHub, so merging still works.

## Commit as the bot

Agents never push to a default branch: they push a branch and open its pull request through `post.yaml`, which signs it. They commit as the bot with `git -c user.name='vinceamstoutz-github-ai-bot[bot]' -c user.email='359789700+vinceamstoutz-github-ai-bot[bot]@users.noreply.github.com' commit …`. GitHub then shows the bot's name and avatar; commits the bot creates through the API are also Verified.

## Setup

1. A GitHub App named `vinceAmstoutz GitHub AI bot`: no webhook, installable **Only on this account**, with the repository permissions **Actions: Read-only**, **Checks: Read and write**, **Contents: Read and write**, **Issues: Read and write**, **Pull requests: Read and write** and **Workflows: Read and write** (to fix pull requests that change workflow files, such as GitHub Actions updates). Its logo is the bot's profile picture.
2. Installed on this repository and on every repository it watches.
3. In this repository:
   - variables `BOT_CLIENT_ID` and `BOT_REPOSITORIES` (comma-separated names);
   - secrets `BOT_PRIVATE_KEY` and `BOT_MEMORY_KEY` (any long random string, such as the output of `openssl rand -base64 32`);
   - Claude access, one of: Anthropic workload identity federation (no stored key: a rule trusting this repository's `main` branch, then the `BOT_ANTHROPIC_FEDERATION_RULE_ID`, `BOT_ANTHROPIC_ORGANIZATION_ID`, and optionally `BOT_ANTHROPIC_SERVICE_ACCOUNT_ID` and `BOT_ANTHROPIC_WORKSPACE_ID` variables), the `CLAUDE_CODE_OAUTH_TOKEN` secret (from `claude setup-token`, billed to the subscription) or the `ANTHROPIC_API_KEY` secret. A stored credential is used first; when it is refused or exhausted (usage limit, expired token) and federation is configured, the bot retries through federation automatically;
   - for the security audit: the `ANTHROPIC_API_KEY` secret, which the auditor needs;
   - for production errors: the `BOT_BUGSINK_URL` variable (such as `https://example.bugsink.com`), the `BOT_BUGSINK_PROJECTS` variable mapping repositories to Bugsink project ids (`my-repository=1,other=2`) and the `BUGSINK_TOKEN` secret (a Bugsink API token with `issues:read`, `events:read` and `issues:comment`);
   - for slow pages: the `BOT_SITES` variable mapping repositories to sites (`my-repository=https://example.com`), and optionally `BOT_SLOW_TTFB_MS` (800) and `BOT_SLOW_TOTAL_MS` (1500);
   - optional: `BOT_WORK_MODEL`, `BOT_REVIEW_MODEL`, `BOT_REVIEW_EFFORT`.
4. In each watched repository, for instant mentions and reviews: [`templates/bot-mention.yaml`](templates/bot-mention.yaml) and [`templates/bot-review.yaml`](templates/bot-review.yaml) in `.github/workflows/`, and a `BOT_DISPATCH_TOKEN` secret holding a fine-grained token limited to this repository with **Actions: Read and write** only.
5. In each repository, a ruleset requiring signed commits on the default branch (see above).
